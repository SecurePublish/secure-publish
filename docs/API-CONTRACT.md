# Console ↔ Worker API contract (V1)

Cameron console (`/workspace/secure-publish-app/`) calls these when `window.SP_API_BASE` is set (or `?api=`). Default = **stub** (no backend).

Auth: session cookie from OAuth (same-site / CORS credentials). CLI `Authorization: Bearer` (publish credential) is accepted **only** on `POST /api/panels` and `PATCH /api/panels/:id/name`. Any other `/api/*` request that carries `Authorization: Bearer` is `401` and never falls back to the session cookie. `POST /api/session/revoke` is handled before that two-route rule (Bearer only revokes its own token). Email from a Bearer token is `trim().toLowerCase()`.

**Host:** `/api/*` is served only when `Host` is exactly the app host (`app.securepublish.work`, from `APP_HOST` or `OAUTH_CALLBACK_ORIGIN` / the existing OAuth callback origin). Panel subdomains, apex, `workers.dev`, and any other host get the same clean 404 as an unknown path. CLI `login` / `publish` / `rename` use `SECURE_PUBLISH_API_BASE` default `https://app.securepublish.work`.

**Cookie CSRF:** `POST`/`PATCH`/`PUT`/`DELETE` under `/api/*` authenticated by the session cookie require (1) `Origin` exactly equal to one `CONSOLE_ORIGIN` entry (`new URL().origin`, no suffix matching) and (2) `Content-Type` media type `application/json` (parameters such as `charset` allowed). Otherwise `403 {"error":"csrf_origin"}` or `403 {"error":"csrf_content_type"}`. `Authorization: Bearer` (CLI publish credential) and unauthenticated `/api/device/code` + `/api/device/token` are exempt. `/api/device/bind` (console cookie) is not. A request with a cookie and no Bearer is always checked.

| Method | Path | Notes |
|--------|------|--------|
| GET | `/api/me` | `{ email, idp, domain, publicDomain, host, customHostname, customVerified, customDomainsEnabled }` — `publicDomain` is `true` when the session email domain is on the Worker public-mailbox list (exact match, case-insensitive). `host` is the serving host only (verified custom with `customStatus: "active"` or subdomain), never `""`. `customDomainsEnabled` is `true` iff var `CUSTOM_DOMAINS_ENABLED` is `"true"`. When a claim exists **and** the flag is on, also `customStatus` (`pending_dns` \| `issuing_cert` \| `active` \| `records_missing`) and `customRecords: [{ type, name, value }]` with names **relative to the registrable domain** (CNAME `share` → `cname.securepublish.work`, TXT `_secure-publish.share` → `sp-verify=<token>`). When the flag is off, never include `customRecords` / `customStatus` (so `cname.securepublish.work` never appears). |
| POST | `/api/panels` | SSO cookie **or** `Authorization: Bearer` publish credential (not a browser cookie). Body `{ html, title?, name?, to? }`. `name` is a read-only URL label (not unique); the Worker normalizes it (NFKD, strip diacritics, lowercase, non-`[a-z0-9]` runs → `-`, trim `-`, max 60 at a hyphen boundary). Empty after normalize → no name. New panels get a random 10-char code (lowercase base32 `a-z` + `234567`) used as the KV id. `201 { ok, id, url, path, name, host, mode, allowlist, title, publishedAt }` with canonical `url` = `https://{host}{path}` and `path` already normalized (`"/k7f3qx2abc/performance-out-26"` or `"/k7f3qx2abc"` with no name). `name` is the normalized string or `null`. `400 company_requires_work_domain` if the publisher's email domain is public and the body has no email allowlist (`to` / company mode) — nothing written to KV. Allowlist (`to`) still works for public-domain accounts. `409 no_host` if the account has no host. `413 html_too_large` over 1.5MB. `401` with no session. Publisher is always the signed-in account. |
| POST | `/api/device/code` | No session. Starts a one-time login. `{ device_code, user_code, verification_url, expires_in, interval }`. `device_code` is 64 hex (CLI polling secret only). `user_code` is 8 chars from `BCDFGHJKLMNPQRSTVWXZ`, displayed `XXXX-XXXX`. `verification_url` is `https://{app host}/device` with **no** `device_code` or `user_code` in the URL. `expires_in` 600, `interval` 2. |
| POST | `/api/device/token` | No session. Poll with `{ device_code }` only (never `user_code`). Pending: `400 {"error":"authorization_pending"}`. Once: `{ access_token, token_type: Bearer, email, host, expires_in }` (12h, publish-only). Replay: `400 {"error":"expired_token"}`. Malformed/non-hex/`user_code`: `400 {"error":"invalid_request"}`. |
| POST | `/api/device/bind` | SSO cookie only (app host). A request carrying `Authorization: Bearer` is `401` (no cookie fallback). No cookie: `401`. Body `{ user_code }` (dash optional, any case, trim/spaces). `device_code` in the body is ignored (treated as missing). Approves the pending device for the session email (`trim().toLowerCase()`). Success: `200 {"ok":true}` — no `device_code` in the response. Single-use: `devuser` mapping deleted after approve. Unknown, expired, reused, or malformed: `404 {"error":"device_code_invalid"}` (identical body). After 5 failed binds per session email **or** 50 failed binds globally in 10 minutes: `429 {"error":"device_code_rate_limited"}`. Cookie CSRF Origin + JSON content-type required (`403 csrf_origin` / `csrf_content_type`). |
| POST | `/api/session/revoke` | `Authorization: Bearer` drops that publish credential. |
| GET | `/api/panels?scope=mine\|company` | `{ host, panels: [{ id, title, name, path, url, publisherEmail, mode: company\|allowlist, allowlist[], publishedAt, publishedLabel?, views, viewers?: [{email,first,last,firstAt,lastAt}] }] }` — `title` from panel record, fallback `"untitled"`. `name` is the stored normalized label or `null`. `path` is already normalized: `"/k7f3qx2abc/performance-out-26"` or `"/k7f3qx2abc"` with no name; legacy 24-hex panels use `"/{24hex}"` (or `"/{24hex}/{name}"` if named). `url` is `https://{host}{path}` when `host` is set, else `null`. `views` is the total count for every listed panel. **`viewers` is publisher-only:** included only when the authenticated email equals that panel's `publisherEmail` (case-insensitive); omitted entirely for colleagues, `scope=company` listings of someone else's panel, and legacy panels with no `publisherEmail`. `firstAt`/`lastAt` are ISO 8601 UTC (`2026-10-07T00:47:12.000Z` or `null` if empty/invalid); the console formats them. `first`/`last` are legacy time-only labels (`HH:mm` pt-BR). `scope=company` does **not** list `mode: company` panels whose company domain is a public mailbox domain. |
| PATCH | `/api/panels/:id/access` | body `{ mode, allowlist[], sendInvite? }` — publisher only (SSO cookie). `Authorization: Bearer` → `401` (no cookie fallback). `400 company_requires_work_domain` when `mode: company` and the publisher's email domain is public — nothing written. ACL unchanged. |
| PATCH | `/api/panels/:id/name` | body `{ name }` — publisher only (same ownership as PATCH access; same Origin/CORS as other mutating `/api` routes). SSO cookie or `Authorization: Bearer` publish credential. `name` null or empty string removes the label. Worker normalizes non-empty values. `200 { id, name, path, url }` with canonical `path`/`url` (`name` normalized or `null`). |
| PUT | `/api/hosting/subdomain` | `{ slug }` → `{ host }`. `400 reserved_slug` for product/infra names (case-insensitive; nothing written). `400 invalid_slug`. `409 subdomain_taken` |
| PUT | `/api/hosting/custom` | `{ hostname }` — feature flag `CUSTOM_DOMAINS_ENABLED` must be `"true"` else `403 custom_domains_disabled` (nothing written). Hostname is normalized (trim, lowercase, IDN→punycode, strip trailing dots) **before any KV write or Cloudflare call**. `400 invalid_hostname` (port/path/userinfo, IPv4/IPv6, garbage, bare public suffix). `400 reserved_hostname` for `securepublish.work` / `*.securepublish.work` / `workers.dev` / `pages.dev` (exact or `endsWith('.'+suffix)`, never `includes`). `400 apex_domain_not_supported` when the hostname equals its eTLD+1 (ICANN Public Suffix List). Pending claims do **not** lock the hostname: each account may hold its own pending claim and TXT token. Exclusive lock `host:custom:{hostname}` is written only when a claim reaches `active` (kept through `records_missing`, no TTL). A new claim replaces **this account's** previous hostname (delete its CF hostname if any; drop the lock only if this account owns it). **No Cloudflare create on claim.** `409 hostname_taken` if another account already holds the lock (`active` or `records_missing`) — no CF create, lock never overwritten. `200 { host, customHostname, customVerified:false, status:"pending_dns", records:[{type,name,value}] }` with relative DNS names. Customer DNS: CNAME `{relative}` → `cname.securepublish.work` and TXT `_secure-publish.{relative}` → `sp-verify=<opaque-token>` (per-account). |
| DELETE | `/api/hosting/custom` | SSO; session owner only. Deletes the Cloudflare custom hostname (if any), the KV lock, and claim fields. Serving falls back to the subdomain; leftover customer CNAME then serves nothing. `{ ok: true }`. `404 no_custom_hostname` if none. Cloudflare API failure → `502 cloudflare_error`. |
| POST | `/api/hosting/custom/verify` | Flag must be on (`403 custom_domains_disabled`). No body. Same TXT-recheck function as the daily cron. DoH TXT of **this account's** token first. Lock is re-read immediately before any Cloudflare create; `409 hostname_taken` if another account holds `host:custom:{h}` (no CF create, lock unchanged). Always `200 { status, records, customHostname }` for DNS/SSL progress: `pending_dns` (TXT missing/mismatch, or CF hostname not active) \| `issuing_cert` (hostname active, SSL not; **no lock yet**) \| `active` (TXT ok + hostname active + SSL active → write lock with no TTL, `customVerified: true`, serving host = custom hostname) \| `records_missing` (TXT gone after the hostname was active: stop serving, stop 301, subdomain serves, **lock stays**). If already `active`, verify still re-checks TXT. If TXT returns on `records_missing`, restore once CF hostname+SSL are ok. Cloudflare API errors → `502 cloudflare_error` (never fake success). `400 no_custom_hostname`. |
| GET | `/auth/providers` | `{ providers: ["google", ...] }` — public; only IdPs with both CLIENT_ID and CLIENT_SECRET. CORS + credentials like `/api/*`. Console `/signup/` and `/login/` call this to choose SSO buttons. |
| GET | `/auth/{google\|microsoft\|github}` | OAuth start (Miles/John); callback pinned to `app.securepublish.work` so session cookie is `Domain=.securepublish.work` |
| GET | `/auth/handoff` | **`app.securepublish.work` only** (anywhere else → identical panel 404). `?host=&return=&nh=`. `host` must be an **active** verified custom hostname (same normalization as claim, exact KV equality). `return` must be a relative path (`/` start, no `//`, no backslash). `nh` is the SHA-256 (base64url) of the customer-host `__Host-sp_handoff` nonce (32 random bytes); the nonce itself never goes to `app.`. No app session → 302 `/_auth/login?return_to=/auth/handoff?...`. With session → one-time code (32 random bytes, base64url) in KV `handoff:{code}` TTL 60s bound to `{hostname, email, nonceHash}` → 302 `https://{hostname}/_auth/handoff?code=&return=`. Invalid host → default page. `Cache-Control: no-store`, `Referrer-Policy: no-referrer`. Login `next`/`return_to` may be an `https` URL on a custom host only when that exact normalized hostname is in KV with `customVerified: true` and `customStatus: active` (no suffix/substring match). |
| GET | `/_auth/handoff` | **Verified customer host only** (anywhere else → identical panel 404). Consumes the code (read + delete). Succeeds only when the request `__Host-sp_handoff` cookie hashes to the stored `nonceHash` **and** Host exactly equals the bound hostname. Success: clear `__Host-sp_handoff`, mint a **new** `__Host-sp_session` (`Secure; HttpOnly; SameSite=Lax; Path=/`; **no** `Domain`; TTL = app sessions); 302 to the validated relative return path **without** the code. Any failure (missing cookie, wrong nonce, expired/reused code, wrong host): burn the code, clear `__Host-sp_handoff`, **no session**, **403**. Browser (`Accept` includes `text/html`): lang-aware PT/EN expired-signin page; button `href` is `return` only after `isSafeRelativeReturn`, else `/` — never echo the raw parameter. Success and error: `Cache-Control: no-store`, `Referrer-Policy: no-referrer`. `/api/*` on customer hosts returns the same unknown-panel 404; `__Host-sp_session` is never accepted for `api: true`. Pages never set sessions. |
| GET\|POST | `/auth/logout` | On a custom host: clear `__Host-sp_session` then 302 `https://app.securepublish.work/auth/logout`. On our zone: clear `secure_publish_session` (same Path/SameSite/Secure/Domain as login) → 302 first `CONSOLE_ORIGIN` + `/signup/` (ignores `?next=`; `Cache-Control: no-store`) |

Lock A: `mode=company` = same email domain after SSO. Not Workspace/Entra/GitHub Org membership.

Public mailbox domains (Worker `PUBLIC_EMAIL_DOMAINS`, exact match): company publish and `PATCH` `mode: company` return `400 {"error":"company_requires_work_domain"}`. Existing `mode: company` panels whose company domain is public return **403** to everyone except the panel's `publisherEmail`. Same-domain viewers are not exempt.
